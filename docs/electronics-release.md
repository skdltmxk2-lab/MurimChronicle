# 전자공학 실험실 첫 버전

경로: /admin/electronics. 기존 관리자 인증을 사용한다.

## 구현한 기능

- 63열 단일형 830홀 보드와 2장 구성, 중앙 분리/연속 전원레일 선택.
- 목표 회로에서 소자·점퍼·장비 연결점을 생성하고 실제 구멍 연결을 역으로 검사.
- 사용 영역 확대, 소자/핀/점퍼 hover, 선택 연결 강조, 좌표별 상세, 핀 위치 수동 변경과 실행 취소.
- 전체 설계에서 단계별 조립 안내, 사용자별 조립 진행, SVG·TXT·프로젝트 JSON 내보내기.
- 소자 카탈로그 141개. 데이터시트 핀 확인 35개, 범용 물리 모델 8개, 미검증 98개를 구분.
- 일반 회로 예제 16개, 실험0~10 및 연도별 프로젝트 가이드 15개.
- 관리자 전용 자료 인식 API와 AI 없이 동작하는 배치·검증 API.
- ‘ChatGPT 설계 가져오기’로 외부에서 작성한 회로/프로젝트 JSON을 같은 엔진에 전달.
- 계정별 브라우저 자동 저장과 비공개 Supabase Storage 프로젝트 저장·조회.
- 빵판 중심 화면: 실험·자료·저장함은 필요할 때 여는 창으로 제공하고 상세 정보·검사 결과는 접어서 표시.
- 저항, 커패시터, OP AMP, 반도체, 기타 IC/소자, 점퍼선, 계측기 표시를 개별 전환하거나 한 종류만 선택. 표시 여부와 무관하게 전체 회로를 검사하며 SVG는 현재 보기 기준으로 내보냄.
- 오른쪽 Gemini 채팅에서 현재 회로·실제 배치·선택 소자를 참고해 질문. 프로젝트/계정 변경 시 대화 분리, 회로 편집 시 진행 중 답변 중단. 좁은 화면에서는 채팅을 빵판 아래에 표시.
- 명확히 지정된 전원·접지를 실제 +/− 레일로 배선하고, 사용 중인 분리 구간·보드 사이만 점퍼로 연결. GND와 음전원은 별개로 배치하며 실제 도통에 따른 레일 이름을 표시. 수동 RC 예제에는 없는 DC 전원을 추가하지 않음.
- 소자 전체와 계측기 접점을 구멍에 맞춰 드래그 이동. ‘주변 자동 재배치’가 켜져 있으면 이번에 옮긴 항목을 고정하고 나머지를 재배치하며, 꺼져 있으면 해당 항목만 이동하고 기존 점퍼는 유지. 이동 취소 지원.
- ‘변경 검증’에서 실제 도통, 단락·끊김, 중복 홀, 장착 영역 겹침, 핀 간격·DIP 중앙골 배치를 검사. 검사 이후 설계가 바뀌면 이전 결과를 현재 결과처럼 표시하지 않음.
- 몸통은 전체 이동, 리드 소자의 삽입점은 해당 다리만 이동. 저항·다이오드·인덕터는 2~8피치, 일반 커패시터·전해 커패시터·LED는 1~4피치 범위에서 같은 보드·같은 연결 영역의 서로 다른 열을 사용한다. 변형한 다리 형태는 이후 전체 이동에서도 유지한다. DIP·헤더·3핀 소자는 몸통으로 이동한다.
- 전해 커패시터의 음극 띠와 극성 표시는 현재 핀 배치 방향을 따른다. 기본 간격과 다른 리드 성형은 실물 길이·몸체 확인 경고를 표시한다.
- 흰색/스톤 회색과 차콜 테마. 전원·접지·배선·오류 색상은 유지한다.
- 잘못된 프로젝트 파일은 현재 작업을 변경하기 전에 거부하며, 늦게 도착한 클라우드 저장 응답이 최신 로컬 편집을 덮지 않도록 한다.

## 검증

- 엔진 16개, 인식 11개, 프로젝트 API 9개, 설계 API 8개, 클라이언트 계정 격리 4개, 표시 필터 5개, 채팅 API 12개, 전원 레일 10개, 이동·재배치 9개, 저장/작업 상태 9개, 개별 핀 11개, 포인터 이벤트 5개: 총 109개 회귀 테스트.
- 기존 문항·렌더 검증을 포함한 prebuild와 TypeScript 검사.
- 운영용 Next.js 빌드. 격리된 네트워크에서는 기존 사이트의 외부 글꼴 다운로드가 실패하므로 네트워크가 가능한 실행 환경에서 확인.
- RC·CE·741의 실제 SVG 출력을 PNG로 렌더해 배선·리드·명칭 겹침을 점검.
- 레일 업데이트 후 RC·분압기·741 SVG를 다시 렌더해 GND/+전원/−전원 표시를 점검.
- 개별 핀과 몸통 이벤트 구분, 프레임 전 드롭, Esc/blur/캡처 해제, 극성 반전, 필터·툴팁·선택 갱신은 실제 TSX를 실행하는 Node 하네스 및 SVG 출력으로 검사한다. 실제 브라우저 조작 검증을 대체하지 않는다.

## 성능 측정

품목별 배치 후보·예약 영역을 재사용하고 소자/접점 조회를 인덱싱한다. 배선 경로의 가림 검사를 캐시하고 사용 중인 접점으로 레일 도통을 분석한다. 드래그·툴팁 변경은 애니메이션 프레임으로 합치며, 보드의 830/1660개 구멍은 선택·점유 정보가 바뀔 때만 다시 생성한다.

재현: `npm run benchmark:electronics -- --baseline 3da96b0a5e9897c2081cca2498143b33f8846a07`. 로컬 Node, 보드 2장·분리 레일, 워밍업 3회 후 7회 중앙값이다. 소스 컴파일·브라우저 렌더링·네트워크 시간은 제외한다. 측정 장비와 부하에 따라 수치는 달라진다.

| 시험 회로 | 이전 배치 | 변경 배치 | 결과 |
| --- | ---: | ---: | --- |
| 40개 저항 부하 | 17.93ms | 3.40ms | 40개 배치, 연결 검사 통과 |
| 80개 커패시터 부하 | 29.01ms | 3.61ms | 80개/160핀 배치, 연결 검사 통과 |
| 80개 저항 용량 초과 | 31.12ms | 2.81ms | 48개만 배치, 용량 오류 유지 |

16개 예제와 위 3개 부하의 배치·검사 결과·레일 도통은 이전 구현과 동일하다. 지원 입력 상한은 80소자·2보드이며, 모든 종류의 소자 80개가 물리적으로 들어간다는 뜻은 아니다. 회로 분할·더 많은 보드·시뮬레이션은 별도 확장 작업이다.

## 지원 상태와 남은 작업

- 예제는 일반 회로이며 수업의 모든 원회로를 검수 완료한 상태는 아니다. 학생 보고서의 값·설명을 정답으로 자동 등록하지 않는다.
- 실제 빵판 사진에서 모델명과 내부 레일 단절을 확정하지 않았다. 830홀 보드 프로필은 선택한 일반 모델이며 실물의 구조와 맞춰 확인해야 한다.
- BC109C TO-18의 삼각 리드, 센터탭 변압기 등은 전용 물리 프로필과 실물 방향 검수가 더 필요하다. 미지원 부품을 임의로 다른 품번으로 치환하지 않는다.
- ‘연결 검사 통과’는 구현한 빵판 연결 모델 기준이다. 소자 정격·열·성능·계측기 내부 공통접지까지 모두 검증했다는 뜻이 아니다.
- 드래그 검증도 목표 회로의 연결과 물리 배치 검증이며 실제 이득·파형 동작을 보증하지 않는다. 먼 위치로 옮길 때는 ‘전체 빵판’ 보기와 확대·스크롤을 사용한다. 기존 저장 배치는 자동 덮어쓰지 않고 ‘레일을 사용해 전체 재배치’로 갱신할 수 있다.
- 파형·회로 시뮬레이션·DSP 수치 실행과 장비 직접 제어는 후속 구현이다. 현재는 관련 실험의 설정과 절차를 제공한다.
- 자료 인식과 질문 채팅은 서버 GEMINI_API_KEY 설정이 필요하다. 기존 사이트의 Gemini 모델 설정을 공유하며 키는 브라우저에 전달하지 않는다. 로컬 개발 환경에는 키가 없어 실제 Gemini 호출을 시험하지 않았다.
- 클라우드 저장은 서버 SUPABASE_SERVICE_ROLE_KEY를 사용하며, 저장 API에서 관리자와 소유자 prefix를 검사한다. 실계정 저장·조회는 별도 확인이 필요하다.
- 브라우저 자동화 호스트가 연결되지 않았으며 네이티브 브라우저도 현재 URL 확인 제한으로 자동화가 중단됐다. 실제 로그인 세션의 클릭·채팅 검증은 완료하지 못했다.

## 관리자 API

- POST /api/admin/electronics/analyze — PDF/사진/조건에서 회로 초안 추출.
- GET/POST /api/admin/electronics/design — 현재 규약/카탈로그 조회 또는 회로 배치·검증.
- GET/POST /api/admin/electronics/projects — 내 프로젝트 조회 또는 저장.
- POST /api/admin/electronics/chat — 검증한 현재 회로·배치를 참고하는 Gemini 질의응답. 대화는 서버에 저장하지 않음.

모든 API는 기존 관리자 세션의 Bearer 토큰을 검증한다. 공개 API 키나 인증 우회 경로를 추가하지 않는다. 상세 사용법은 electronics-agent-workflow.md를 참고한다.
